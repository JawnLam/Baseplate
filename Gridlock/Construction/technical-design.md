# Gridlock — Technical Design

> **How exactly it is built.** This document owns engine internals, the technology stack, algorithms (including the exact PRNG), failure modes, and the AI opponent. Gameplay semantics are owned by `game-rules-spec.md` (this document implements, never redefines, GL-RS rules); wire formats by `interface-contracts.md`; storage fields by `data-dictionary.md`.

## 1. Technology stack (each item verified against its registry on 2026-07-20)

| Choice | Version floor | Role | Why |
|---|---|---|---|
| Node.js | 24 LTS "Krypton" (v24.18.0; 22 LTS acceptable) | Runtime for server, engine tests, sim harness | One runtime everywhere; LTS support window |
| TypeScript | 7.0.2 | All source code | One language across all four components; types encode the schemas |
| Vite | 8.1.5 | Client build + dev server | Standard, fast, PWA-friendly |

## 2. Repository layout (one repository, npm workspaces)

```
gridlock/
├── packages/engine/     # C-1: pure rules engine — ZERO runtime dependencies
├── packages/protocol/   # shared Zod schemas + TS types (wire + balance data + log events)
├── packages/server/     # C-2: game server (imports engine, protocol)
├── packages/client/     # C-3: PWA (imports protocol only — NEVER engine; see §3)
├── packages/sim/        # C-4: sim harness CLI + AI policy (imports engine, protocol)
└── data/                # balance data JSON (from game-rules-spec.md appendices)
```

The client must never import the engine: anything the engine could compute client-side is concealed information leakage by construction (PRD GL-NFR-2). A lint rule enforces the import ban.

## 3. Engine design (C-1)

### 3.1 Core types (shapes; storage-level detail in `data-dictionary.md`)

- `MatchConfig` — the loaded balance data (tunables, matchup matrix, pool, both playbooks) + `seed`.
- `MatchState` — immutable snapshot: phase, possession index, score, LOS, down, distance, per-player: CP, hand (card instance ids), deck order, discard, consecutive-autocommit counters; RNG cursor; regulation/tiebreak bookkeeping.
- `PlayerView` — the projection of `MatchState` legal for one player to see (own hand, public state, per GL-RS-11). **The server only ever serializes `PlayerView`, never `MatchState`.**
- `DownInput` — `{commit: cardInstanceId}` | `{declare: 'normal'|'punt'|'fg'}` | `{scout: true}` | `{auto: true}` | `{concede: true}`.
- `EngineEvent` — the match-log event union (`interface-contracts.md` §5 defines the serialized form).

### 3.2 API (pure functions; no mutation, no I/O)

```
createMatch(config)                          → {state, events}
legalInputs(state, player)                   → LegalInputSet
applyInput(state, player, input)             → {state', events}   // commit/scout/declare/concede
resolveDownIfReady(state)                    → {state', events}   // no-op unless both committed
view(state, player)                          → PlayerView
replay(config, eventLog)                     → {finalState}       // must reproduce exactly (GL-AT-15)
validateBalanceData(json)                    → ok | list of violations (GL-RS-38; Zod + invariant checks)
```

Determinism contract: every function is pure; all randomness flows from the RNG cursor inside `MatchState`; wall-clock time never enters the engine (the server translates shot-clock expiry into `{auto: true}` inputs — GL-RS-12).

### 3.3 PRNG (frozen for determinism — PRD GL-NFR-1)

- Algorithm: **PCG32** (`state' = state × 6364136223846793005 + increment`; output = 32-bit XSH-RR of the pre-advance state), 64-bit state, odd `increment` fixed at `1442695040888963407`.
- Seeding: `seed` is a 64-bit unsigned integer generated by the server from OS entropy at match creation and recorded in the match header (log + DB).
- `uniformInt(a, b)`: rejection sampling — draw 32-bit values, reject those ≥ `2^32 − (2^32 mod n)` where `n = b − a + 1`, then `a + (value mod n)`. (Unbiased and portable; no floating point in yardage draws.)
- Event draw (GL-RS-28): one draw of `uniformInt(0, 9999)` compared against cumulative probabilities in basis points, in the fixed order INC, SACK, INT, FUM, BRK.
- Shuffle (GL-RS-20): Fisher–Yates from the top index downward, each swap index via `uniformInt(0, i)`.
- **One stream per match**, consumed strictly in the orders fixed by GL-RS-2/-23/-28/-31/-32 plus AI draws (§5). Every consumption emits a `draw` log event with its purpose tag, so replay divergence is detectable at the exact draw.

### 3.4 State machine

Phases: `AWAIT_PLAYBOOKS → COIN_FLIP → [possession loop: UPKEEP → COMMIT → RESOLVE → (transition)] → REGULATION_END → (tiebreak loop) → MATCH_END`. Transitions are exactly the GL-RS rules; the engine rejects any input not in `legalInputs` with a typed reason (never throws on bad player input — server maps reasons to protocol errors).

## 4. Server design (C-2)

- **Session registry:** `device_id` → `player_id` issuance and `resume_token` rotation (identity rules: `data-dictionary.md`); one WebSocket per player; reconnect swaps the socket under the same session (client UX: `ux-spec.md` §6).
- **Matchmaking:** single FIFO queue; pair the two oldest; after ⚙ `matchmaking_backfill_seconds = 15` (a balance-data tunable, same file as game tunables) unpaired players get an AI match (PRD GL-FR-10). Both players may be given the same playbook (GL-RS-17).
- **Match orchestrator** (one instance per live match): owns the engine state, the two shot-clock timers, the scout window, and the match-log appender. Input pipeline: Zod-validate → `legalInputs` check → `applyInput` → `resolveDownIfReady` → persist events (write-ahead) → broadcast views. Single-threaded per match; inputs are processed in arrival order (the engine's commit semantics make order irrelevant between the two players' commits).
- **Hidden-information enforcement:** the orchestrator broadcasts only `view(state, player)` per player and the shared reveal payloads the engine marks public. No other serialization path exists.
- **AI hosting:** when a match has an AI side, the orchestrator asks the AI policy (§5) for its input at commit start; the AI's "thinking" delay is a uniform draw in ⚙ `[1, 4]` seconds (presentation only, from a non-match RNG — never the match stream, so replays stay exact).

## 5. AI opponent (C-4, policy module)

- **Information rule:** the AI receives exactly `view(state, aiPlayer)` — the same legal view a human gets (no oracle access; PRD GL-FR-6 applies to it).
- **Policy (v1, deterministic given its inputs):** for each affordable card, compute expected value against a *belief distribution* over the opponent's category: prior = opponent playbook's category frequencies (public, GL-RS-17), updated by this drive's observed reveals (simple frequency decay, factor ⚙ 0.7). EV = Σ belief(cat) × cellScore(cell after tier/clause), where cellScore = band midpoint adjusted by event probabilities × fixed utilities (TD +70, INT/FUM −60, SACK −10, BRK +25 ⚙). 4th-down declarations compared on the same utility scale (FG EV from the GL-RS-32 table; punt EV = field-position swing). Tie-break between equal-EV inputs: lowest CP cost, then hand order — fully deterministic.
- **Difficulty:** one knob ⚙ `ai_noise ∈ [0,1]`: with probability `ai_noise` (drawn from the match stream, logged) the AI plays a uniformly random affordable card instead of the EV choice. Default 0.15.
- **Scouting:** AI scouts when CP ≥ scout cost + 2 and belief entropy exceeds ⚙ threshold 0.8 — cheap heuristic, tunable.

## 6. Failure modes & responses

| Failure | Response |
|---|---|
| Server crash mid-match | **Live matches are void**: on restart, matches without an `end` event are marked `void` in the DB; players see a "match abandoned" result (not counted as loss). Match-log write-ahead means the log is still complete up to the crash for debugging. Prototype-deliberate: no live-state checkpointing. |
| Balance data invalid at load | `validateBalanceData` fails → server refuses to swap, keeps serving the previous valid set, logs the violation list (GL-RS-38). A server cold-start with no valid set refuses to start (fail loud). |
| Client disconnect | Session survives ⚙ `resume_window_seconds = 120`; shot clock keeps running (GL-RS-36 — disconnection is not a game state); resume re-sends the current `PlayerView`. |
| Clock skew / client-side timer drift | Server clock is the only clock; clients render a deadline timestamp, never enforce it. |
| SQLite corruption / disk full | Runbook procedures (backup restore; disk alerts) — `runbook.md` §5. Engine and logs are append-only, minimizing write amplification. |
| Replay divergence detected (GL-AT-15 failing) | Treated as a release-blocking engine defect; the per-draw purpose tags (§3.3) localize the first divergent draw. |

## 7. Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Floating-point probabilities in resolution | Basis points + integer draws avoid cross-platform float drift in the determinism contract. |
| xoshiro / Math.random / seedrandom dependency | PCG32 is ~15 lines, fully specified above, dependency-free — the determinism contract should not rest on an unpinned third-party implementation. |
| Live-match crash recovery via event-sourced resume | Real cost (checkpoint discipline, migration of in-flight timers) for a prototype whose matches last ≤ 6 minutes; void-on-crash is honest and cheap. Revisit with a real population. |
| Monte-Carlo tree search AI | v1 EV policy is deterministic, debuggable, and strong enough to playtest against; MCTS is a balance-analysis luxury deferred until the rules stabilize. |
| Separate WebSocket message signing / anti-tamper | The server validates every input against `legalInputs`; a tampered client can only send legal moves for itself — already the security model (PRD GL-NFR-2). |
